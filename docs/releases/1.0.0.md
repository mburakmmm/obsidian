# Obsidian 1.0.0 release notes

Status: release preparation. The manifest, source version, version test, example expectation, changelog and MIT license are aligned at `1.0.0`; no `v1.0.0` tag, stable GitHub Release or stable registry ref exists yet.

## Stable core

- Explicit synchronous `Logger` instances with numeric thresholds, typed scalar fields and immutable-by-copy records.
- Immutable explicit context binding with request, trace and span correlation identifiers.
- Deterministic single-line text and `obsidian.log.v1` JSONL output.
- Fail-closed message and field redaction before filters, diagnostics and sinks.
- Bounded memory capture, stdout console, append-only file and single-process size-rotating file sinks.
- Exact logger routing, per-sink thresholds, bounded diagnostics and callback re-entry protection.
- Typed configuration and all-or-nothing logger construction.

The stable candidate is exactly the protected `v0.9.0-beta.1` core inventory. No public core symbol or schema property was added or removed during promotion. Nyx, Aether and Quartz adapters remain preview and are not covered by the core stable compatibility promise.

## Candidate evidence

Commit `ccc9e411ca8dc5087f8fcc12b017d16b481c50d6` and CI `42968550569` passed the stable-candidate contract on macOS ARM64, Linux x64 and Linux ARM64 with LLVM and QBE: 22 behavioral files/467 assertions/0 skips per backend, three expected compile-fail fixtures, seven capability probes, three pinned ecosystem probes/36 checks, all examples, benchmark smoke and 8,000-event file/rotation stress smoke.

The public registry clean-install gate resolved `v0.9.0-beta.1` to immutable commit `c2379fe493b8eb431220f8a5c2b1bd12b13f1867` under checksum-verified NOX 2.1.0 and ran the stable-candidate API/schema/import/version contracts on LLVM and QBE. This proves beta-to-stable-candidate source compatibility; it does not substitute for running the same gate against a future stable tag.

## Compatibility

- Required compiler baseline: NOX 2.1.0 at source commit `fd107b922c67a804520dc30f849039d977542f6c`.
- Supported evidence matrix: macOS ARM64, Linux x64 and Linux ARM64; LLVM and QBE.
- Windows and unlisted platforms/backends remain unsupported because they have not been executed.
- `obsidian.log.v1` remains the stable-candidate schema. Consumers read properties by name, tolerate documented optional correlation IDs and ignore unknown properties.
- Documented core API incompatibilities after a stable release require a new major version.

## Known limitations

- Dispatch is synchronous. Async queues and shared-logger thread safety are not provided.
- Console output is stdout-only; stderr and recoverable broken-pipe handling are unavailable in the pinned public API.
- File `flush` is not `fsync`; disk-full, partial-write and stable-storage durability are not claimed.
- Rotation is size-based, trusted-directory and single-process only; no time rotation, compression, encryption or hostile-directory race resistance is claimed.
- Structured values are scalar only; nested objects/arrays, exception stacks and source metadata are absent.
- Redaction cannot discover every arbitrary secret embedded in prose. Applications must use allowlisted metadata.
- Preview adapter compatibility is limited to the exact revisions in `../ecosystem.md`.
- The natural `Logger.trace` spelling is unavailable on the pinned LLVM backend; use `trace_event` or `log(TRACE, ...)`.

## Benchmark and provenance policy

Existing reproducible measurements remain machine-specific observations, not performance guarantees. The exact release commit must run LLVM/QBE benchmark smoke in CI and the full local benchmark/stress commands with `dirty=false`; results will be recorded in the public release evidence rather than inferred from older baselines.

No Git signing key, automatic tag-signing configuration or artifact-attestation workflow is configured for this preparation. Unless infrastructure is deliberately added and verified before tagging, `v1.0.0` will be an annotated but unsigned tag and the project will make no signed-provenance claim.

## Remaining release gates

1. Commit this aligned preparation and pass the full supported CI matrix at that exact commit.
2. Run the full LLVM/QBE benchmark and bounded file-stress commands from the clean preparation commit.
3. Verify the immutable release preflight against one annotated `v1.0.0` tag candidate without pushing it early.
4. Push the tag only after all pre-publication gates pass; do not retarget it.
5. Verify the tag-driven matrix and public GitHub Release.
6. Submit the exact tag with the external `noxc` operator session, then run the credential-free public-registry install gate against its peeled commit.
7. Close Phase 12 only when release, registry, tag, changelog and evidence identify the same commit.
