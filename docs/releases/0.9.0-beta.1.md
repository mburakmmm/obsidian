# Obsidian 0.9.0-beta.1 release notes

Status: release preparation. The manifest, source version, dated changelog and MIT license are aligned; no immutable tag or release artifact exists until the preparation commit passes the full matrix.

## Highlights

- Explicit synchronous `Logger` instances with typed scalar fields, immutable-by-copy records and context binding.
- Deterministic single-line text and `obsidian.log.v1` JSONL output.
- Fail-closed field/message redaction before filters and sinks.
- Bounded memory capture, stdout console, append-only file and single-process size-rotating file sinks.
- Exact routing filters, bounded sanitized diagnostics and callback re-entry protection.
- Preview Nyx `v0.24.0`, Aether `v0.9.0` and Quartz `v0.9.15` adapters without reverse core dependencies.
- Normative beta API inventory, schema compatibility policy and migration guidance.

## Compatibility

The protected candidate surface is listed in `../public-api.md`. Optional adapters remain preview. JSON consumers require `schema_version == "obsidian.log.v1"`, read properties by name, tolerate its optional correlation IDs and ignore unknown properties. Pre-beta internal consumers should follow `../migration.md`.

## Known limitations

- NOX 2.1.0 is pinned; Windows and unlisted platforms/backends are unsupported.
- Dispatch is synchronous. Async queues and shared-logger thread safety are not provided.
- Console output is stdout-only; stderr and recoverable broken-pipe handling are unavailable in the pinned public API.
- File `flush` is not `fsync`; disk-full/partial-write durability is not claimed.
- Rotation is size-based and single-process only; no time rotation, compression, encryption or hostile-directory race resistance.
- Structured values are scalar only; nested objects/arrays, exception stacks and source metadata are absent.
- Redaction cannot discover every secret embedded in arbitrary prose. Applications must use allowlisted metadata.
- Preview adapter compatibility is limited to the exact revisions above.
- The natural `Logger.trace` spelling is unavailable on the pinned LLVM backend; use `trace_event` or `log(TRACE, ...)`.
