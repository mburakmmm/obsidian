# ADR-0020 — NOX 2.2.38 tooling and release SBOM

Obsidian 1.1 selects NOX 2.2.38 at `7f879fe0ecb972dc9994ee1e8f420d4aaa0cdd9a` for formatting and release tooling. CI continues testing 2.1.0 consumers and 2.2.38 consumers on LLVM and QBE across the three hosted platforms. The toolchain upgrade preserves the v1 API, field types and JSONL schema.

The 2.2.38 formatter writes the carriage-return literal as an escape. The primary format check uses 2.2.38 and the earlier compiler still runs behavior and package tests. Optional narrowing, scalar pattern matching and module export restrictions can be considered for separate changes with a demonstrated compatibility benefit.

The release workflow generates a CycloneDX 1.5 SBOM from a clean tagged checkout with the checksum-pinned Linux x64 compiler extracted outside the checkout. This placement keeps the compiler runtime out of the package source scan. The generator compares two raw outputs and verifies package identity, zero components and the pure-NOX declaration. It then supplies the manifest version when the compiler omits that field. The attached file describes the tagged package. The GitHub release and noxpkg submission use the same immutable tag, with the registry ref and commit verified independently.

Publisher attestation is optional. Obsidian 1.1 publishes with the operator's existing authentication and records absent signing separately from checksum and commit verification. The async lifecycle decision remains in [ADR-0011](0011-async-dispatch-no-go.md).
